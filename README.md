# TRUGS onboarding kit

Bindings: `agent` is you; `entry` is this README; `primer` is [PRIMER.md](PRIMER.md);
`map` is [map/published.trl](map/published.trl); `sentence` is a TRL instruction;
`graph` is its compiled JSON graph.

```trl
AGENT agent SHALL READ FILE entry THEN READ FILE primer.
AGENT agent SHALL READ FILE map.
AGENT agent SHALL WRITE RECORD sentence THEN VALIDATE RECORD graph.
```

TRUGS represents typed nodes, named relationships and hierarchy as JSON.
TRL is its constrained English sentence form. Write sentences to communicate;
compile them to inspect and validate their structure. A valid graph does not prove
that an agent or a program obeys the instruction.

## Four types

**Describe** maps sources into graphs. **Say** expresses graphs as sentences.
**Compute** represents calculations as graphs. **Govern** uses graphs to govern
work; its runner is coming. Read the [specification](https://github.com/TRUGS-LLC/TRUGS)
for depth. The calculator has its own compute vocabulary and compiler.

## Install

This checkout contains the unreleased trugs-agent 2.0.0 installer. The existing
index releases are older; do not use them to install this kit. From this checkout,
with the build tools and runtime dependencies already installed from an
offline wheel bundle, install the local candidate into your current Python
environment. The helper builds in temporary storage and installs that wheel;
it does not place instructions in the checkout.

```sh
python tools/install_local.py
```
<!-- expect: {"status": 0, "stdout": "PASS: local trugs-agent 2.0.0 installed\n"} -->

Expected stdout: `PASS: local trugs-agent 2.0.0 installed`; exit status 0.

After installing the CLI, use its install subcommand in your own project. It lists
every destination before writing. Existing files require a terminal and an explicit
`yes`. The offline checker also exercises installation in a temporary project.

The installed version command is:

```sh
trugs-agent --version
```
<!-- expect: {"status": 0, "stdout": "trugs-agent 2.0.0\n"} -->

Expected stdout: `trugs-agent 2.0.0`; exit status 0.

In a project, `trugs-agent install` lists AGENTS.md, CLAUDE.md, the Cursor rule
and plugin manifest, then prints `PASS: trugs-agent check` on success (status 0).
The explicit `trugs-agent check` command prints that same PASS line (status 0).
The installation check executes both commands on its temporary project.

## Self-check

Compile hello, validate, decompile, recompile and compare. A vocabulary miss or
invalid placed instruction fails the installed check. Try the graph loop first:

```sh
bash examples/hello/check.sh
```

## The map is TRL

Bindings: `reader` is you; `published` is map/published.trl; `repositories` are
its repository records. The map gives live/coming groups, installation routes and
links to each repository's own instructions; those instructions remain there.

```trl
AGENT reader SHALL READ FILE published THEN READ EVERY RECORD repositories.
```

[Read the map and its bindings](map/README.md). [Compiled graph](map/published.trug.json).
The [repository index](folder.trug.json) is generated by trugs-web map with hidden directories included.

## What is unpublished

This kit's 2.0.0 package and trugs-web 2.1.0 are local candidates. This text does
not assert that trugs.ai/onboard is served. TRUGS-VIEWER is a demonstration, not
in active development. TRUGS-TRL, TRUGS-LAW and the Govern runner are coming,
with no date. The [fixed tasks](eval/README.md) are for a later clean-machine run.
